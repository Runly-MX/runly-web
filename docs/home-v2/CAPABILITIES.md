# Runly Web 2.0 — capacidades y límites de comunicación

Fecha de corte: 2026-11-09. Investigación de código, documentación y contenido público; no certificación de producción.

## Cómo leer la evidencia

Repositorios: **Web** = `Runly-MX/runly-web`, base inicial `038de45`, actualizada por otra sesión a `66b6943` durante la investigación; **ERP** = `Runly-MX/runly-erp`, checkout hermano `../runly`, base inicial `80627dbad`; **Hub** = `Runly-MX/runly-developer-hub`, base `67ea4ef`. Se leyeron también cambios locales preexistentes, sin modificarlos. El catálogo, las traducciones y las capacidades de Web estaban pendientes al empezar y otra sesión los consolidó durante la auditoría. Un commit local o `help/capabilities.json` del ERP sirven de orientación, no prueban una release desplegada.

Estados comerciales:

1. **Disponible y comprobado**: documentado públicamente y con soporte en el código revisado. El alcance de comprobación se declara por fila; no implica prueba autenticada ni disponibilidad en todas las instalaciones.
2. **Implementado con disponibilidad limitada**: código o evidencia de laboratorio; falta acreditar despliegue, configuración, interfaz o acceso general. Laboratorio no significa staging desplegado.
3. **En desarrollo**: implementación incompleta o integración pendiente explícita.
4. **Planeado**: roadmap o propuesta; no ofrecer como funcionalidad.

**No verificado** es un límite de evidencia, no un quinto nivel de madurez. Cuando no se puede acreditar disponibilidad general se usa 2 conservadoramente, sin inventar un programa piloto.

## Decisiones de producto antes de publicar la home

- Responsable de producto debe confirmar qué versiones de Studio, Website, automatizaciones y Marketplace están habilitadas para clientes; adjuntar versión, entorno, fecha y responsable a cada ascenso de estado.
- Confirmar listing público y estado de revisión del plugin antes de usar «oficial» en contexto ChatGPT. Autoría Runly, conexión privada y aprobación por OpenAI son afirmaciones distintas.
- Confirmar qué categorías tienen recursos realmente publicados. Existencia de filtros, schemas o fixtures no acredita oferta.
- La home puede describir la plataforma extensible desde ya; cada demostración debe conservar el estado de la capacidad. Si no se acredita lanzamiento, usar contexto de demostración o acceso según implementación y mantener el CTA comercial de consulta.
- Revalidar promesas actuales de uptime, backups diarios, cifrado, plazos, escalabilidad y precios con evidencia operativa/comercial. Código y copy anterior no prueban esas garantías.

## Límites de esta fase

No se ejecutaron módulos, builds, cambios de datos ni pruebas de producción. El grafo ya estaba indexado y se usó para descubrir rutas y símbolos; sus resultados se contrastaron con archivos actuales porque parte del contenido local es más reciente. No se inspeccionaron secretos ni se reutilizaron logs productivos. Esta matriz no convierte evidencia histórica de tests en pruebas ejecutadas durante esta sesión.
